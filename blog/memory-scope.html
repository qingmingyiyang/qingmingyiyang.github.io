记忆工作台：先做好资料整理

2026-09-12 修订 · 熊帝权 · 根据个人经历整理，AI 协助成文

最初是为了找资料

文章、文档和讨论记录散在不同地方，存的时候没有统一整理，等到要用时，又得重新找。把资料交给 AI 接着做事，还要再解释一次前面讨论过什么。我做 Chriptmas OS，就是想解决这个麻烦。

我希望它能帮我提取和归档资料，也希望它像一个工作台，记住当前的任务，再调用工具完成接下来的工作。做着做着，资料管理、长期记忆、任务规划和自动执行都加了进来。

想做的太多，各部分也越来越难衔接

原型用 React 做页面，Electron 做桌面程序，Python 提供本地服务。功能增加后，页面、数据和任务状态都要在这几部分之间传递。我既想把资料整理做好，又想让 Agent 执行任务，系统变得越来越复杂。

原型已能展示部分资料整理和交互功能。我进一步把资料归档和任务工作台拆开考虑，让每一部分围绕明确的任务推进。

先检查一份资料能不能存好、找回

下一轮，我准备先做完这几步：保存原文和出处，提取有用的信息，由人核对、修改后保存；下次需要时，能找回原文，也能把整理结果复制给 AI。

原文和摘要要分开，资料里的事实和自己的判断也要分开。AI 整理后的文字可能看着很顺，但遗漏了条件，或者把推测写成了事实。能找到出处、让人修改，对这个工具来说都很重要。

这些是接下来要验证的内容，重构还没有完成。自动规划、多角色协作和更多工具接入，等资料整理稳定以后再考虑。

先做了一个简单的上下文卡片

整理作品集时，我先做了一个手动填写的小工具。填入来源、原文、事实和判断，就能生成 Markdown，复制或下载后交给 AI 使用。它没有自动提取和检索功能，是把这几步先做清楚的一个尝试。

下一轮要把问题记下来

这次实践让我积累了从个人需求出发设计原型、识别功能依赖和调整优先级的经验。下一轮将围绕一份资料的提取、核对和复用记录实际表现。

下一轮，我准备保存输入材料、失败现象、自己的判断、AI 做的修改，以及再次检查的结果。这样才能看清，一次修改到底解决了什么问题。
